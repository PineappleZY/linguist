## 6.5 改了什么

这一版不加新能力，只修会误导学习或悄悄丢数据的地方。

### 1 · 练习：不自动朗读，提示之后才能播放

进题与切到下一个词时都不再发声。顶栏的扬声器在**看过至少一级提示之前是禁用的**（提示文案「先用一次提示」），点过灯泡后即可手动播放；`handle('replay')` 也走同一条护栏，键盘或脚本绕不过去。任何语言都遵循这一口径——中文与日语看过提示后播放等于给出读音，这是明确接受的取舍。不支持语音合成的环境里，按钮照旧不出现。

### 2 · 练习：拼错后重新输入不再回弹

根因是：拼错后状态停在 `wrong`，输入处理却把 `current.typed`（上一轮的错误拼写）写回输入框，于是按任意键都看见上次的错误答案。现在 `applyInput` 遇到 `wrong` 会先开一次新尝试——清空 `typed` / `marks` / `note` / `expectedTail`，**但保留已揭示的答案**；下一次提交重新判定。`Retry` 按钮走同一路径，两种重试行为一致。

### 3 · 随机：锁定语言时不再吞掉外语词

固定语言时，`surpriseTarget` 只接受「模型没给语言」或「给的就是这个语言」；模型明确给出另一种语言时，只有在该词的非拉丁字形本就与固定语言冲突、且那个语言属于在用语言时才接受，其余返回空并重抽。未知语言（如 `Portuguese`）与已退休的 `es` / `it` 继续一律拒绝。手打查询不受影响。

### 4 · 剩下的界面硬编码

| 位置 | 现在用的键 |
| --- | --- |
| 主题 `Auto / Light / Dark` | `theme.auto/light/dark` |
| 两档模型说明 | `model.flash.hint` / `model.pro.hint` |
| 词源事实标签 `via / attested / certainty` | `field.via/attested/certainty` |
| 解释语言面板的标题与 aria | 复用 `entry.explainIn` |

静态守卫测试已扩到这四处：视图源码里再出现这些字面量就失败；中文界面渲染出的 Profile 必须含「自动 / 浅色 / 深色」且不含 `Light` / `Dark`。

### 5 · 文档模式的两条边界真正生效

- **真截断**：文档落盘前把 `text` 截到 `limits.document.keepSource`（60,000 字），并在写入副本上置 `textTruncated: true`；内存对象保留全文，所以当前会话里续跑与换解释语言重跑不受影响。视图里那句「超出部分未保留」由此才真正对应事实。
- **id 用全文**：`documentId` 改为对完整归一化文本做一次哈希，同名、同长、后半段不同的文件不再共用一个 id。

### 6 · 取消星标：行先留在当前页

新增内存集合 `ns.session.keptUnstarred`；星标页的行集 = 真实星标行 ∪ 本次停留里刚取消星标的行。点掉星标后，这一行**原地变成空心星**，语言分组与计数不变；再点一次即重新加入。集合只在**离开星标页**时清空（切到别的标签再回来，或刷新页面，这一行才真正消失）。单词本归属按真实数据解除，不受影响；当前停留期间铅笔仍会抽到它——这是停留式反馈的必然结果。

## 6.4 改了什么

### 第一次没拼对，也算「不会」

以前只有「答对」与「跳过」两种结局：拼错了可以重来，重来对了就当作掌握。现在多一种结局——**第一次提交就拼错的词，即使后来改对了，也记为「不会」并排进下一轮**；它与跳过的词共用一条复习队列，按发生的先后轮转，所以一轮真正结束的条件是「每个词第一次就写对」，或者你手动关闭。

进度点因此有五种状态：已完成（实心强调色）、跳过（强调色 35% 淡点）、**不会（琥珀 `--warn` 45% 淡点）**、当前（细描边）、未到（灰）。「声调待注意」（音节对、声调错）仍算答对，不计入「不会」。

### 界面本地化补全

自查出七处仍在源码里写死的文案，全部改为走 `strings.js`：

| 位置 | 处理 |
| --- | --- |
| 星标页右上角总开关 | 复用 `dict.history.expandAll/collapseAll`（截图里的 `Collapse all`） |
| 新建单词本的输入框 | 复用 `fav.bookPrompt` |
| Profile 模型说明 | `profile.model.hint` |
| 易混词表格表头 | 复用 `field.word/meaning/note` |
| 读音分组小标题 | `field.on/kun/special` |
| 比较级提示 | `entry.irregularComparison` |
| 中文卡字段与送假名 | `field.primarySense/figurativeSense/now/okurigana` |

并加了一条**静态守卫测试**：视图源码里再出现 `'Expand all'`、`<th>Word</th>`、`window.prompt('`、`Irregular comparison`、`On readings` 这类形态直接失败。顺带清掉了 `strings.js` 里历史遗留的 18 行重复键（同一 key 在两个位置各写一次）。

### 随机只取可选语言

`Surprise` 的提示词以前按**整张语言表**（含已退休的意/西）随机，客户端又把不认识的语言回落成英语——于是 `sobremesa` 以西语词条出现、`sexta-feira` 被当成英语去查并得到「不是英语单词」的卡片。现在：提示词只列五种在用语；客户端拿到结果先校验语言，未知（如 `Portuguese`）或已退休（`es`/`it`）一律视为无效，按与「重复」相同的路径重抽，仍不行就提示重试，**绝不把外语词当英文查**。手打查询不受影响。

## 6.3 改了什么

### 按语言练习

「练习来源」原来只有两个层级：全部星标、某个单词本。现在中间多了一层——**只要某语言有星标条目，就会出现在下拉里**（母语名 + 该语言的可练词数；旧数据里的意/西排在在用语言之后）。选中它，下面的星标列表只剩这一语言，铅笔也只从这一语言里抽词，于是一轮五个词不会跨语言。

没有新增文案：语言名用各自母语名，其余复用现有键。选中状态与来源选择一样只在内存里，刷新回到「全部星标」。某语言有星标条目但没有可练词（例如缺读音的中文词）时，它仍会出现、计数为 0，铅笔会给现有的「没有可练的读音」提示。

### 图谱随版本

`docs/feature-map/graph.json` 现在带 `changes[]`：每个版本一条，写清新增与改动了哪些节点。`build.mjs` 会拒绝「版本升了但没写变更」的图谱，6.0 的测试套件也会比对 `features.json` 的版本，不一致就红并告诉你重跑哪条命令。这一版就是它的第一次生效（图谱里 `Practice source` 标为新增，`Starred` 标为改动）。

## 6.1 改了什么

### 1 · 练习：提示变成提示

以前进入一道题只有一排下划线，释义藏在灯泡里；点一次灯泡才看见释义，点第二次看见首字母。现在：

- **词性与释义在题目上直接从第一帧就在**（词性小标签 + 释义，最多三行）；释义按该源语言在 Profile 里设定的解释语言取——若当前词条是用别的解释语言生成的，会去历史里找同词、同语言、同模型、配置语言的另一条；都没有才回落到词条自带那句。**不额外发请求**。
- 灯泡第一级：拉丁语系给 **IPA**；中文给**声调型**（如「声调 1 + 1」）；日语给**拍数**（如「4 拍」）。中文与日语的读音就是答案本身，所以永远不作为提示。第二级才是「以「x」开头」。

### 1b · 跳过当前词，练完再回来

- 右上角原本的关闭按钮改成 **`Skip`（跳过当前词）**，图标是双箭头；**左下角的 × 才是关闭**，它在输入、答对、答错、第二轮回环的任何时刻都可以点，关掉即结束整组。
- 一组（默认五个）练完后，若还有跳过的词，就从**第一个被跳过的词**开始再练一轮；这一轮里再跳过的词排到下一轮。所以「整组结束」= 每个词都至少被认真写过一次，或你主动关闭。跳过次数不设上限——每一轮都要你主动点才会继续，关闭又始终在场，不会把人困住。
- 进度点有四种状态：已完成（实心强调色）、**被跳过（同色 35% 的淡点）**、当前（细描边）、未到（灰）。第二轮的点阵代表这一轮要补的词。
- 单字模式（从词条页头部进入）不显示跳过：那里没有「下一个」，显示一个只会关掉当前词的按钮是误导。

### 2 · Cards 列表的卡名随界面语言

每张卡新增了五种界面语言的名称（`CONFIG.cardTitle`）。**只有 Profile → Cards 这张列表**用它：界面切成中文时看到「义项 / 词源 / 核心义」，切成法文时看到 « Sens / Étymologie / Sens central »。词条页的卡标题保持不变，仍是「英文 · 母语术语」——那是学习用的对照，两侧靠当前界面语言那半对得上。

同一处还做了两件事：

- **只列该组真正会出现的卡**。以前四个分组各列 42 张（整个目录），中文界面下会看到西语专属的 `Ser 与 Estar`、日语专属的 `読み` 挤在「英语、法语、德语」里。现在按提示词实际字段推导出一张适用表：拉丁组 25 张、日语组 17 张、中文组 16 张、句子组 9 张，组头的人数也按这个数显示。
- **每行多了「置顶」**：四十行的列表里，把末尾一张卡挪到最前不再需要点几十次。置顶、上移、下移都作用在**看得见的这张列表**上，再把它接回完整顺序，所以不会出现「点了没反应」。
- **删掉两张死卡**：`serEstar`（Ser and estar）与 `arabismos` 只有西语会产出，而西语在 5.0 已撤下。它们从目录、阅读顺序、卡名表、渲染器与西语提示词里一并移除；导入的西语旧词条仍可打开、仍显示其余卡片。目录现在是 40 张。
- **补齐 5 处漏掉的母语注**（自查本地化时发现，卡片会出现但标题缺了那一半）：`doublets` 缺法语、`government` 缺德语、`culture` 缺日语与中文、`pronunciation` 缺日语。并加了约束测试：凡适用表里列出的语言，该卡必须有对应术语。

### 3 · 每个语言族一个常驻的「恢复本组」

四个分组（英/法/德、日语、中文、句子分析）的标题行右侧各有一个「恢复本组」，**组收起时也能直接点**；它只清空该组，其它三组不动。底部「全部恢复」保留。偏好存储结构不变，没有任何数据迁移。

### 4 · 文件模式加 DOCX

`.docx` 当 ZIP 解开取 `word/document.xml`：`<w:p>` → 段落、`<w:br/>` → 换行、`<w:tab/>` → 制表符，域代码（`<w:instrText>`）丢弃。零依赖，用浏览器内置的 `DecompressionStream('deflate-raw')`，压缩与未压缩两种条目都支持。

失败各有明确文案：`.doc`（旧二进制格式）提示另存为 `.docx`；超过 10 MB 拒绝；环境不支持解压时说明；压缩包损坏单独提示。**图片仍不支持**——DeepSeek 的公开接口是纯文本的，读不了图；将来若做，默认走本地 OCR + 按语言下载语言包（英/德/法各约 4 MB、中约 20 MB、日约 30 MB），那是独立的一轮。

### 5 · 保留原文件的换行与空格

- 抽取阶段保留**所有换行与空行**，只把行内连续空格压成一个、去掉行尾空格；行首缩进保留为一个空格，制表符原样保留。
- PDF 不再把所有文字块用空格拼成一段，而是按纵坐标重建行；明显大于行距的间隔变成空行（段落）。
- DOCX 按段落重建。
- 译文同样保形：提示词要求**段落一一对应**、该空行处留空行，译文卡用 `white-space: pre-wrap` 渲染，单换行不会被折成空格。

### 6 · 翻译写入「信达雅」

文档翻译规则现在明写三层，并且**以信为先**：信 —— 不增不删、不跳句、人名与术语保留原形；达 —— 母语者读不出原文语法，译意不译词；雅 —— 符合原文自身的文体与节奏，不堆辞藻。冲突时准确优先，且不得加入原文没有的评论。

## 6.0 改了什么

### 1 · 新手教程：先修 bug，再更新内容

原来的第 4 步（解释语言）与第 7 步（填 Key）在首次运行时必然落空：要指的解释语言默认值在 Profile、要指的输入框只在自己没填 Key 时存在。落空本身是设计好的（卡片居中显示），但 `place()` 会把上一步算出的 `top` 写成**行内样式**，而行内样式优先于 `.tour-card.is-centred` 的居中规则——卡片于是停在屏幕外，按钮也点不到，看起来就是"卡住"。

现在的位置计算是一个纯函数 `tour.layoutFor(box, viewport, cardSize)`：往上、往下、居中三选一，数值一律夹在视口内，每次写入前不做任何"保留上一步"的假设；目标不在视口里先 `scrollIntoView` 再测量；窗口缩放或滚动时重新定位。步骤可以声明自己在哪个屏幕（`route`），运行器先过去再定位，结束后回到进入前的屏幕——包括为演示文件面板临时切换的查询类型。九步的顺序与文案在五种界面语言里都有。

### 2 · 释义收紧，`Core meaning` 承担细节

- 卡片 `core` 从 `Semantic core` 改名为 **`Core meaning`**，位置不变（仍是 Word DNA 首卡）。
- 它现在要的是**精确的中心义**：一到两句平实的话点明本质义、语义场，以及它和第一条释义的关系；**明令禁止比喻与意象**——那是 `Mnemonic` 卡的事。
- `senses[].definition` 收紧为**一个短句**：不许罗列同义词、不许复述词源、不许与相邻义项重复。字数上限按解释语言分别设定（中 ≤24 字、日 ≤40 字、英/法/德 ≤12 词），并且规则放在**公用的行级规则**里，七种源语言一起生效——这正是中文与日文释义曾经最长的地方。
- 旧词条不受影响：`core_metaphor` 仍会渲染，键名与 schema 未变。

真实调用实测（`contend` / en → 中文，2026-10-16）：

```
core_meaning   25 chars — 努力与对手争夺同一目标，或在分歧中坚持自己的说法。
definitions    4 senses, 11/9/11/12 chars  (上限 24 字)
```

### 3 · 卡片偏好（Profile → Cards）

四个分组：**英/法/德**、**日语**、**中文**、**句子分析**。每组列出该组的全部卡片（按当前阅读顺序），每行两个箭头调整先后、一个开关决定显隐；组内可 `Reset this group`，全区可 `Reset all`。默认什么都不改就等于现状——偏好为空时渲染顺序与 5.0 逐字相同。

顺序是唯一真源 `CONFIG.cardOrderFor` / `CONFIG.resolveCardPrefs`，词条页与句子页都从它派生，分组标题与「该线报错只出现一次」的锚点也跟着过滤后的顺序走。偏好随设置一起导出/导入；旧版本留下的未知键会被忽略而不是把列表截断。

### 4 · 更名 `Linguist`

- 命名空间 `window.RADICLE` → `window.LINGUIST`（代码、工具、测试、HTML 共 109 处），`CONFIG.appName = 'Linguist'` 仍是文件名、缓存名与备份类型的来源。
- **名字不翻译**：五种界面语言的 `app.name` 都是 `Linguist`。**简介与副标题随界面语言变化**，界面语言默认改为中文（`uiLang: 'zh'`，`auto` 仍是一个选项）。
- 简介重写为「以词根为纲的词典：五种语言，整句与整份文件，都从词根、词缀与字形讲起」，同步 manifest、`index.html` 与四份 README。
- 图标：五套方案见 `design/icon-concepts/app-icon-options.png`（生成脚本 `make_app_icons.py`）。**本次落地的是方案 1「词根三分」**——单一主干三处分枝、四个节点，说的是"一个词根带出一族词"，在任何尺寸下都读得出来，也不依赖某一种文字。要换只改一行：

```powershell
python design/icon-concepts/make_app_icons.py --concept 3 --set
python design/icon-concepts/make_app_icons.py --previews   # 重出方案对比图
```

### 5 · 文件查询（第四个查询类型）

类型分段变成 `Auto / Word / Sentence / File`，界面语言里 "File" 就是"文件"。

- **先读文件，再问你要不要花钱**：选定文件后立刻解析并显示文件名、字数、预计请求数；未选语言或未选文件时按钮禁用。
- **文件语言由你指定，绝不猜**（下拉里没有 Auto）。猜错了代价是整篇文件的四个请求。
- 可读格式：纯文本 / Markdown / CSV / 字幕（srt、vtt、ass 等）/ HTML（去标签）/ PDF（本地内置 pdf.js 抽文本）/ DOCX（6.1 新增，零依赖解开 OOXML）。扫描版 PDF 会明确说"没有文字层，本轮不做 OCR"；加密 PDF、旧版 `.doc`、超过 10 MB 的 DOCX 各有单独提示；图片不支持。
- 长度：≤40,000 字一次请求；40,001–200,000 字按约 20,000 字分块、块间重叠 1,000 字，**顺序**执行并显示 `第 i / n 部分`，最后加一次合并请求把各块要点并成全局概要（共 n+1 次）；超过 200,000 字直接拒绝并回显实际字数。
- 四张固定卡：`Summary`（全局脉络）、`Translation`（按块顺序拼接的完整译文）、`Vocabulary`（去重后的词汇表，含读音与原文例句）、`Register & genre`（体裁、语体、年代与备注）。中途可停止，已完成的块保留，并可"从第 i 部分继续"。
- 文件可以收藏，在 Starred 里与单词、句子并列（`Words / Sentences / Files` 三条小组标签只在同时存在两种以上时出现）；文件永不进练习池。

实测（`dist/measure/measure-sample-de-long.txt`，44,885 字德语，中文解释，2026-10-16）：

| 请求 | 耗时 | 输出 | 上限 | 截断 |
| --- | --- | --- | --- | --- |
| part 1 | 23.8s | ~6,750 tok | 8,000 | 无 |
| part 2 | 24.2s | ~6,760 tok | 8,000 | 无 |
| part 3 | 14.3s | ~3,450 tok | 8,000 | 无 |
| merge | 2.7s | ~613 tok | 1,600 | 无 |
| **整体** | **65.0s**（4 次请求） | — | — | 无 |

这次实测改了两个数字：`maxTokens.document` 由 6,000 提到 **8,000**（单块实测输出约 10,150 字符，天花板留出余量），并新增 **`api.documentTimeoutMs = 90000`**——单块最慢 24.2 秒，对着原本统一的 45 秒只剩 1.9 倍余量，而词条查询仍保留 45 秒不变。文件这一条线是目前唯一"一次操作要等一分钟"的路径，所以它单独计时。

### 顺带修的

- **卡片渲染器按页取用**：句子页与文件页有 `translation` / `register` 两个同名卡，之前文件页会拿到句子页的渲染器，导致"文体"卡空着不显示（截图核对时发现，现有测试已补上这一条）。
- **Profile 里几处写死的英文**（Install app / API key 按钮 / Show、Hide / 连接测试文案）改为走 `strings.js`；界面语言的默认值是中文这件事也有了自己的断言。
- **`1.0/`–`5.0/` 完全未动**，包括 5.0 里的 0.1.0 之类历史字符串。

## 验收清单

自动化（`node 8.0/web/tests/smoke.js`，806 条）覆盖 6.5–7.2.1 的全部基线，加上 8.0/8.1.2 的 Root Atlas、词根星标、个人词根地图、Context-to-Root、RootEntity/alias、星标同步、同根词查询、缓存命中、反查/翻译入口和清理后的版本兼容；打包链路（白名单、离线包内联 pdf.js 与 worker、SW 预缓存、`linguist_8.1.2.html`、dist 里不留上一代产物）。

需要你在浏览器里确认的：

1. **练习**：查一个词点练习按钮，进来就看到词性与释义；点灯泡先出音标，再点出首字母；中文题点灯泡给声调、日语题给拍数，都不给读音。
2. **跳过**：在收藏夹里开始一组练习，右上角点 `Skip`，看进度点留下一个淡点；把剩余的词练完，确认回到刚才那个词；想退出时左下角 × 随时可用。

7. **Profile → Show the tour again**：中英界面各重放一次，确认不再卡住，跨页步骤定位正确。
8. 中文与日文解释语言各查一个词，确认释义短、`Core meaning` 给的是精确中心义。
9. Starred 里确认 `Words / Sentences / Files` 的小组标签与文件行；深浅色各看一遍新图标与四段式类型控件。

## 关于命名

**Linguist**（语言学家）。选它是因为产品的野心写在"学家"而不是"词典"上：它要解释的是**一个词为什么是这个意思**，而不是给出一串对应词。名字在所有界面语言里都显示 `Linguist`——会随界面语言变化的名字不是名字，也无法作为文件名与备份类型的来源；变的是它下面那行简介。

## 最终需要：桌面端与手机端

**本轮不做打包**，但 6.0 的形态是照着"以后要能装箱"写的，四条不变式都进了自动化测试：

1. **资源只走相对路径**，壳子可以直接读 `web/` 或那个单文件；
2. **网络出口只有 `api.js` 一处**，将来要在壳里加代理或改超时，只需要动一个地方；
3. **不引 CDN**：pdf.js 已经内置（`web/vendor/pdfjs/`），离线包把它连同 worker 一起内联，`file://` 下 PDF 依然可用；
4. **Service Worker 始终可选**，壳子在 `file://` 或自定义协议下不注册也不会缺功能。

已定的路线（等你把网页端验收完再开工）：

| 端 | 路线 | 一次性代价 |
| --- | --- | --- |
| Windows | Electron 壳 + 免安装绿色版 `.exe`，直接装那个单文件 | 只需 `npm`，无需 Rust 与 MSVC |
| 安卓 | **本地网页 / PWA**：装到主屏幕或直接打开离线文件，不做 `.apk` | 零工具链 |
| iOS / macOS | 先走 PWA（Safari「添加到主屏幕 / 添加到程序坞」）；真正的 `.ipa` / `.app` 需要 Mac + Xcode + 开发者账号（$99/年） | 以后再说 |

顺带一条实测出来的注意点：**Electron 不带语音合成**（`speechSynthesis` 在桌面版里通常没有可用音色），所以"朗读"按钮必须保持现在的特性检测式隐藏，将来要么用系统 TTS，要么干脆不做。
