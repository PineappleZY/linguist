# Radicle · 智能辞典

像语言学家一样查词：不只给释义和例句，而是把**词源、词根词缀、同源词、文化内涵**一并讲清楚。

> **这里是 5.0。** 这一版把"以词根学习为核心"作为产品主线：查一个词先看到它的 **Word DNA**
> （语义内核 → 词源 → 构词 → 同源家族 → 假同源），然后才是义项。语言收敛为五种（英/法/德/日/中），
> 意/西 retire 但旧词条仍可打开；解释语言可以**每种源语言各设一个默认值**；界面上的每一个下拉
> 都换成了底部动作面板。
>
> 5.0 同时吸收了那份外部前端评审的修复：跨词条竞态、id 碰撞、清除星标的行为、备份完整性、
> 配额写满、发音语言、识别不再无声花钱、存储层 O(n²)、删除可撤销、历史可搜索、练习可退出、
> 输入法冲突。**逐条处理结果见 [REVIEW.md](REVIEW.md)**，其中也写明了尚未做的两条纯打磨
> 项与需要真机验证的项。
>
> **界面本身也可以换语言**（英/中/法/德/日，默认跟随浏览器），与"解释语言"是两条独立的轴：
> 界面语言只改按钮与标签，解释语言决定模型用哪种语言写。306 条文案 × 5 种语言由
> `web/js/strings.js` 统一管理，逐条对照表见 [STRINGS.md](STRINGS.md)——那份表是给母语者复核用的。
> 首次打开还有一段 7 步的聚光灯引导（也可在 Profile 里重看）。
>
> `4.0/`（内部 4.2）已冻结；5.0 用新的 `dict5` 存储前缀，首次打开会问一次要不要导入 4.x 的
> 历史、收藏与单词本——只读源数据，按新 id 去重，可重复执行。

## 4.2 相比 4.1 改了什么

1. **练习图标改成写 `prac` 的键帽。** 铅笔在 22px 下像"新建文件夹"，而且铅笔在别处已经表示"重命名"。现在是一个键帽里写着 practice 的缩写，重命名继续用纯铅笔。候选方案（含 `P` / `pr` 两个变体）与选中理由都在 `design/icon-concepts/make_practice_icons.py`，键帽几何与字号在下图与代码里是同一份。
2. **分组可以收起。** 历史里每个日期标题、收藏夹里每个语言标题与 `Wordbooks` 标题都变成可点的抽屉头，右侧显示条数，默认全部展开；历史标题行与收藏夹来源行各有一个 `Collapse all` / `Expand all` 总开关。折叠状态只在内存里，刷新回到全展开。
3. **句子也能收藏，并和单词分开。** 此前收藏夹整个把句子过滤掉了——句子能星标但看不到。现在句子进入收藏夹与单词本，主分类仍是语言，语言组内用 `Words` / `Sentences` 两个小组标签隔开（只有两种都存在时才显示）。句子永不进练习池（否则单词成句会被判为拼写整句）。
4. **修掉 `AUTO` 分组的根因。** 那不是显示问题：历史行里真的存了 `language: 'auto'`。原因是概览只要返回了 JSON，哪怕里面没有 `language`，也会被当作成功，于是这一行永远写着 picker 的状态。后果不止分组错位——四条深度线会因为没有识别的语言而回落成**英语提示词**，所以那种词条连内容都是按英语分析的。三层修法：
   - **写入时**不再允许：概览没说语言就重查一次，仍不说就当作查询失败并给出 `Language unclear` + 重试，而不是存一个半成品；来源语言是具体语言时回落成该语言。行与词条的语言一律经 `CONFIG.languageByAnyName` 归一（接受 id、英文名、母语名），`auto` 永远不是语言。
   - **句子**在 Auto 下先用一次极小的请求问"这是什么语言"（`prompts.detect` / `api.detectLanguage`，上限 60 token）再分析。这顺带修掉一个既有缺陷：Auto 下的句子此前被当成英语分析。
   - **旧数据**在打开收藏夹时各补一次识别：词用一次完整概览（顺带把 `reading` 与主释义补回来，练习按钮从灰变蓝），句子用语言识别；每个条目每会话最多一次，无 Key 或离线时跳过。识别完成前它们列在最上方、标着 `Language unknown` 并带一个 Identify 按钮，不再冒充一种语言。识别出的语言不是英语时清空该条目的深度内容（那些是按英语提示词生成的），词条页会给出各线的 Generate。

## 4.1 相比 4.0 改了什么

1. **新增第四条请求线 `inflection`（形态线）**，与词源线、用法线、辨析线并行取回、各自独立失败与重试。它承载全部形态数据，因为这是全 app 最大的载荷：实测一个法语动词（七个时态逐人称）约 1136 token。日语与中文没有可供制表的形态，所以只发三条线、也不会出现"第四条未生成"的提示。
2. **动词变位做成全时态逐人称**：英 5 / 法 7 / 德 6 / 意 8 / 西 8 个时态，每个时态六个人称，命令式按各自的人称数（法语三人称）。呈现上每个时态是一行可展开的抽屉，默认全部收起，只显示"时态名 · 6"，卡内再给一个 `Expand all forms` 总开关——否则一张卡就要占据大半屏。语料的形状同时兼容新老两种：`[{person, form}]` 与 4.0 的纯字符串数组都渲染。
3. **补上"性数格"与其余形态**：新增六张卡 —— `Word profile`（词类、子类、及物性、可数性、体、助动词、CEFR 常用度，以及"必须记住的 2–4 条"）、`Noun forms`（性、冠词、复数，德语另有四格变格全表）、`Adjective forms`（法/意/西四形一致；德语给弱/混合/强三套词尾，因为德语形容词只有作定语才变形）、`Comparison`、`Pronouns`（含法语 en/y 与意西的 clitic 顺序）、`Verb + preposition`（法 penser à、意 pensare a、西 pensar en）。德语继续用 `Case government` 与 `Separable prefixes`，英语不出去形容词一致的卡（它没有一致可言，比较级承担其形态）。
4. **废弃三张卡**：`Gender and number`、`Article and plural` 合并为 `Noun forms`，`Principal parts` 并入 `Conjugation`（德语变位卡顶部先渲染 `gehen → ging → gegangen` 三态条，再接时态表）。一张卡负责一种词类的全部形态，不再出现两张卡各讲一半。旧的缓存条目仍能渲染：渲染器会回读 `gender_number` / `article_plural` 这两个旧字段名。
5. **词条页分成四个不可点击的分组标题**：Meaning / Forms / Roots / Culture。十二张卡涨到十三至十五张后，光靠顺序已经读不出结构了；标题只是分区，全局仍只有一个 `Collapse all`。
6. **词条页工具栏可以直接改解释语言**，与 Profile 是同一份设置、同一个默认值（中文）。切换后会按原样重跑整条查询（含原本的语言参数），因为词条 ID 里含解释语言，所以这会是历史里的**新的一条**，旧语言的答案留着；切回去命中缓存秒开、不重复计费。顺带修掉一处旧的不一致：`Regenerate` 在词条语言与当前设置不一致时现在也走这条路径，不再写出"ID 是旧语言、内容是语言新"的缓存。
7. **练习图标换成自己的字形。** 原来借用铅笔，22px 下读起来像"新建文件夹"（而且铅笔在别处已经表示"重命名"）。现在 `write` 是铅笔加一条底线，重命名继续用纯铅笔；候选方案与选中理由都在 `design/icon-concepts/make_practice_icons.py`。
8. 实测回填：4.1 用真实调用测过 `aller`（法）与 `Gift`（德），四条线整体墙钟 7.1–7.3 秒、最慢一条 7.3 秒，`maxTokens.inflection` 定为 4500（实测 388–1136）。`timeoutMs` 仍是 60 秒，与 2.1 当时的余量口径一致。

## 4.0 相比 3.0 改了什么

1. **加意大利语与西班牙语**，可查语言从五种增到七种。两张新卡是语言特有的：西班牙语的 `Ser y estar`（本质与状态的分工，西语最标志性的难点）与 `Arabisms`（阿拉伯借词层——alcohol、azúcar、almohada、ojalá 的 `al-` 前缀至今可见）。意大利语复用现成的性数、变位与双式词卡（cosa/causa、vezzo/vizio）。
2. **卡片标题在非英语源语言下变成「英文 + 母语术语」**，覆盖全部词条卡与句子卡。此前只有少数专属卡带小注——法语词条里 "Senses" 光秃秃、"Conjugation · Conjugaison" 却有小注，这个不一致现在修平了。小注与英文标题相同时省略，所以不会出现 `Collocations · Collocations`。
3. **修掉一处真 bug**：Auto 模式下任何非拉丁输入都被送去"中文释义找英文词"的反查面板，所以输入 `木漏れ日` 得到的是英文候选而不是日语词条。这是源语言只有英法时写的逻辑，3.0 加入日中后没更新。现在 Auto 下的非拉丁输入直接查词，由模型识别语言；只有**手动锁定拉丁语系语言**时才走反查。
4. **查询类型加入 Auto**：Auto / Word / Sentence 三选一，默认 Auto。先用零成本的启发式判断（句末标点、词数或字数），判成词条但模型回 `not_found` 时自动转句子分析——猜错的代价是一秒，不是错答案。显式选 Word 或 Sentence 时不做任何回退。
5. **历史记录按天分段**：此前只有 Today / Yesterday / **Earlier** 三档，前天、上周、上个月全堆在一起看不出是哪天。现在每天一段，标题为 `Today` / `Yesterday` / `Oct 12` / `Oct 12, 2025`；行尾相应改为时刻（今天内保留相对时间），避免与分组标题重复。
6. **界面整理**：查词页控制分两行、语言改下拉（八项）；搜索框内嵌主按钮，去掉与回车重复的整行按钮；Surprise me 收成图标按钮，并在进入词条页前先展示"为你挑了 X"。Profile 的数据区从五个同权重整宽按钮拆成 **Backup** 与 **Reset** 两组，危险操作红色并各自二次确认。收藏夹控件行收成一个下拉加一个铅笔，新建单词本移入列表末行。词条页工具栏去掉计数。
7. **默认解释语言改为中文**；两处语言选择器都显示各语言的母语名（English / Français / Deutsch / Italiano / Español / 日本語 / 中文）。
8. 提示词里三处写死的语言清单（概览的 Auto 分支、语言代码表、Surprise 的选词范围）改为从 `CONFIG.languages` 推导——否则加语言后模型仍以为只有五种。

## 3.0.1 修了什么

四处测试反馈，其中第一处是实质失效而非观感问题：

1. **深色模式下选中态几乎不可见。** 分段控件的选中项用的是 `--card`（`#1C1C1E`），而轨道是半透明填充叠在纯黑上约等于 `#1D1D1F`——两者同色，所以只有深色失效（浅色下轨道浅灰、选中纯白，一直正常）。现在选中面与描边各自有主题变量，浅色 `#FFFFFF` / 深色 `#2C2C2E`，描边走 `inset box-shadow` 以免切换时改变盒子尺寸。承担"当前解析语言""已加入的单词本"两个选中语义的 accent chip 也一并加深了。
2. **句子模式不再按词数判定。** 原先要求至少两个词，而 `words()` 按空格切词——中文句子永远算一个词，任何中文长句都会被拒。现在只保留长度上下限，单个词也可以提交分析。
3. **同形歧义词必须先选择。** 原先只要"输入的形式本身是合法词"就直接查询，于是 `cote` / `côte` / `côté` 这类不会给你选择。现在判据是"是否存在多于一种读法"：候选为空、或唯一候选就是输入本身，才直接查询；否则出候选面板，并把**你输入的形式排在第一并标注 `you typed this`**。前端还会在你输入的形式合法时强制把它补进候选——模型偶尔漏列，而漏列的后果是你看到一个面板却没有"我刚才打的那个"可点。
4. **去掉重复入口。** 主界面右上角的个人图标与搜索行下方的 Favourites 按钮都删掉了，两处导航只由底部三个标签承担。错误提示里的 "Open Profile" 保留——那是缺 Key 时的上下文引导，不是导航。

## 3.0 相比 2.1 改了什么

1. **五种语言**：英语之外新增法语、德语、日语、中文，查询语言由查词框旁的选择器决定（默认 Auto）。词条 ID 因此加入了语言——否则德语 `Gift`（毒药）与英语 `gift`（礼物）、`Rat`/`rat`、`Bald`/`bald` 会共用同一个 ID 互相覆盖。
2. **每种语言一套卡片**。卡片只在适用时出现：法语动词出 `Conjugation`、名词出 `Gender & number`；德语名词出 `Article & plural`、动词出 `Principal parts` 与 `Case government`、复合词出 `Compounds`；日语按词种分成漢語/和語/外来語三套（`Readings`、`Kanji origin`、`Components`、`Word stratum`）；中文按单字/双字词/成语三套（`Character evolution`、`Components`、`Original sense`、`Multiple readings`、`Classical vs modern`、`Classical usage`）。中日文卡片标题是英文并带母语小注，如 `Word stratum · 語種`。
3. **收藏夹独立成一个标签**。按语言主分类，单词本跨语言挂在上面，一个词可同时属于多个本；星标即收藏，单词本是它的子集划分，删本不删词。历史记录仍留在查词页。
4. **练习统一到一个入口**，图标从钥匙改成铅笔。拉丁字母语言拼写、中文默写拼音、日语默写读音或片假名，全部是输入型，共用同一套全屏层。中文的声调分档判定：声母韵母对就放行，声调单独标注。
5. **句子分析**：与词组并列的模式切换，两条并行取回，卡片分组自适应；语法卡按语言各自分类（德语的格与框型结构、日语的助词与敬语、中文的虚词与把字句）。
6. **解释语言可选全部五种可查语言，默认英文**，界面始终是英文。查询语言与解释语言是两条独立的轴，25 种组合都成立。

2.0 与 2.1 的改动清单见上一级目录 `2.0/README.md`。

为了让等待不至于变成干等，深度请求从"一次全量"改成**三条并行**（词源线 / 用法线 / 辨析线），哪条先回来先渲染哪块，单条失败也只影响它自己那块。

### 分享给别人

`web/` 不是要发布的东西（里面带着测试和文档），先打包：

```powershell
node tools/build.mjs
```

产出两样，脚本会先自检再落盘：

| 产物 | 用途 |
| --- | --- |
| `dist/site/` | 可部署的 PWA 文件夹（白名单内容，不含测试与文档），把这个文件夹传上去 |
| `dist/radicle_4.2.0.html` | 单文件自包含版本，双击即用，不走服务器（文件名带版本号） |

**在线分享**：把 `dist/site/` 上传到静态托管，拿到 HTTPS 地址即可分享。推荐 [EdgeOne Pages](https://pages.edgeone.ai/)（腾讯）—— 免费、自动 HTTPS、全球边缘分发，默认域名**无需 ICP 备案**，对大陆受众的可达性优于 Cloudflare / Vercel / Netlify。应用用 hash 路由，所以**不需要任何重写或 404 规则**。

**安装到本地**：站点带了 manifest 与 Service Worker，所以对方可以安装。Chrome/Edge 地址栏会出现安装图标，Profile → Account 里也有 **Install** 按钮；iOS Safari 走"分享 → 添加到主屏幕"。

两条必须讲清楚的边界：安装后**只有应用外壳能离线打开，查词始终需要联网**；无论是否安装，**每个人的 Key 和历史都只在他自己设备上**，你看不到，他们也看不到你的。

**发个文件给别人**：把 `dist/radicle_4.2.0.html` 直接发过去，双击就能用。文件名带版本号，一个文件夹里放几版也分得清。它已内联全部样式与全部模块，并剥掉了 Service Worker 注册（`file://` 没有安全上下文，注册必然失败）。

**发布更新**：改完代码后必须**先提升 `web/sw.js` 里的 `CACHE_VERSION`**，否则已安装的用户会一直拿到缓存里的旧外壳——这里没有服务端失效机制。

### 分享前的验收清单

### 4.2 的验收

1. **练习图标**：词条页头部与收藏夹的按钮应当一眼看出是"写"（键帽 `prac`），重命名仍是铅笔。
2. **收起**：历史里点任意日期标题应当折叠当天、标题右侧显示条数、总开关一次翻全部；收藏夹里语言标题与 `Wordbooks` 同样。刷新后回到全展开（这是设计如此，不是 bug）。
3. **句子**：星标一个句子，它应当出现在所属语言组下的 `Sentences` 里、没有练习铅笔；同一个语言组里同时有单词和句子时，两个小组标签都要出现。
4. **单词本**：把一个词和一个句子同时放进一个本，本内也应分成两段显示。
5. **不再有 AUTO**：收藏夹里不该再出现 `AUTO` 分组。若你之前有语言没被识别出来的词，打开收藏夹时它们应当被自动识别并归位（会花掉每词一次请求）；识别完再打开该词条，原来的内容大概率是按英语提示词生成的，点 Regenerate 重新生成即可。
6. **新查询**：把语言选成 Auto 查一个词，确认词条头部的语言徽标是真实语言；故意查一个模型说不出语言的东西时，应出现 `Language unclear` 而不是一条没有语言的记录。

### 4.1 的验收

1. **查一个法语动词**（如 `aller`）：Forms 组里 `Conjugation` 应有七个时态行，逐行点开确认六个人称齐全；`Conjugaison` 卡里命令式只有三个人称，`passé composé` 带助动词与配合。
2. **查一个德语名词**（如 `Gift`）：`Noun forms` 里应有四格变格表（`des Giftes` / `den Giften` 这些格形要对）；**查一个德语形容词**（如 `giftig`）应给三套词尾而不是性数一致。
3. **查一个西班牙语形容词**（如 `bueno`）应出 `Comparison`，并给出短尾形 `buen`。
4. **英语词条不应出现 `Adjective forms`**，且卡片一张小注都没有。
5. **逐时态展开 / 卡内 `Expand all forms` / 全局 `Collapse all`** 三者互不干扰；换一个词再看，确认上一个词展开的时态没有跟着带过来。
6. **在词条页把解释语言从中文切到 English**：整条应重新生成，历史里出现第二条，旧的一条仍在；切回中文应当**秒开且不再请求**（DevTools 网络面板确认）。
7. **日语与中文词条完全没变**：仍是三张分组之外的旧卡片集，没有 Forms 组、没有 `Word profile`。
8. **练习图标的辨识度**：收藏夹顶行与词条页头部的按钮应当一眼看出是"写"而不是"新建文件夹"。

1. **五种语言各查一个词**，确认卡片集正确：德语名词应出 `Article & plural`、动词应出 `Principal parts` 与 `Case government`；中文单字与双字词的卡片不同；日语外来语出 `Source word` 而不是 `Kanji origin`。同时看词条头部的语言徽标是否是模型真正识别到的语言。
2. **Auto 的歧义词**：查 `Gift`、`Rat`、`Bald` 这类英德同形词，确认识别结果符合预期；再手动锁定语言重查一次，确认两条路径结果不同且都对。
3. **重音模糊输入**：锁定法语后输入 `flaner`，应出现候选；若输入的是 `table` 这类本身就是合法词的形式，应直接出结果不打断。
4. **练习**：从收藏夹选一个单词本点铅笔，确认中文词出拼音默写、日语外来语出片假名书写、英语词是拼写；中文故意漏声调，确认提示的是"声调待注意"而不是判错；日语把送り仮名打错，确认单独点出。
5. **收藏夹**：建两个本，把一个词同时放进两本，确认两本都有且词只星标一次；删掉一个本，确认词仍在收藏里。
6. **句子分析**：五种语言各分析一句，确认语法卡说的是该语言真正的难点（德语的框型结构、日语的助词、中文的虚词）。
7. **解释语言**：把解释语言切到日语再查一个法语词，确认解释变日语而界面仍全英文；再切回英文确认默认值。
8. **实测耗时与 token**：`node tools/measure.mjs Gift de` 可以指定源语言；五种语言各测一次，回填 `maxTokens` 与 `timeoutMs`——2.1 那次实测（4 请求 6.4 秒、最长线约 1000 token）只覆盖英语词条。
9. 确认 3.0 与 2.0、1.0 的历史互不干扰（三版各查一个词，互不可见）。
10. 真机（iOS Safari / Android Chrome）过一遍现有版式——移动端**刻意没有做适配**，只保证能用。

## 阶段二：微信小程序

### 技术方案

- **必须走云函数中转。** 小程序 `wx.request` 只能访问已配置的"服务器域名"，且该域名必须完成 ICP 备案；云函数出网不受此限制。云函数里用 `wx-server-sdk` 的 `getWXContext()` 直接拿 openid——**不需要 AppSecret，不需要 code2session，不需要配置服务器域名**。
- **Key 只存手机本地**（`wx.setStorageSync`），随请求传给云函数，云函数保持无状态、不落库、不写日志。
- **静默登录**：首次云函数调用即拿到 openid。Profile 顶部显示头像昵称，用 `<button open-type="chooseAvatar">` + `type="nickname"` 输入，可选，不填就是默认头像 + Guest。
- **数据隔离**：云数据库集合 `users` / `history` / `starred`，安全规则设为"仅创建者可读写"，按 openid 天然隔离，本地缓存做二次加速。
- 已知取舍：云函数不支持流式输出，沿用"骨架 + 分段渐入"；`deepseek-v4-pro` 开思考模式的长响应有触及 60 秒上限的风险，需实测，超时则对深度块强制关闭思考模式。

### 搭建与实装（已按官方文档核实）

1. **注册小程序**：个人主体即可，邮箱激活；在微信开发者工具建项目、填 AppID。
2. **备案**：2023-09-04 起新增小程序必须**先完成备案才能上架**，入口在小程序后台首页【去备案】。个人备案必需材料只有个人有效身份证件，其余（小程序负责人现场核验照片、互联网信息服务承诺书、真实性核验单）都在平台内完成，最后过工信部短信核验。词典/工具类**不属于**前置审批范围（前置审批针对新闻、出版、药品和医疗器械、网约车、文化、广播电视、宗教、互联网金融、校外培训等）。
3. **服务类目**：选【工具 → 信息查询】（官方释义"适用于提供信息查询功能"，且在《备案服务内容选择指引》中明确标注"个人备案：可选"）。名称、简介、头像须与实际功能一致，不得有隐藏类目。**微信认证非必需**，个人主体不认证不影响发布；如需认证要付第三方审核服务费，金额以下单页为准。
4. **配置《用户隐私保护指引》**：涉及头像昵称等用户信息时必需。
5. **开通云开发**：自 2025-02-19 起，每个没有云环境的小程序可创建**一个免费体验环境**（未发布阶段无需续费，发布后到期时间变更为上线后一段时间），基础套餐 19.9 元/月（含 20 万次云函数调用 / 2GB 存储 / 2GB 数据库）。注意套餐到期 7 天后未续费会释放资源且数据不可恢复。
6. **部署云函数与数据库集合** → 上传代码 → 提交审核（通常 1–7 天）→ 发布。
7. **合规配套**：接入内容安全校验过滤用户输入；界面显式标注"答案由 AI 生成"。

小程序的生成式 AI 内容标识要求，我没有从官方文档取得确定结论——官方文档只覆盖了备案与前置审批清单，没有直接答案。提交审核前请按当时生效的规则再核对一次（包括《人工智能生成合成内容标识办法》一类对 AI 生成内容的显式标识要求）。这一条在方案里始终作为"待核实"处理，不作为既定事实。

## 关于命名

**Radicle**（植物学义：胚根，种子中发育成主根的部分；来自拉丁语 *radicula*，词根 *radix* = 根）。它把"词根"这件事写进了名字里，和 *radical* / *eradicate* 同源，7 个字母、两个音节、无歧义读音。

名字收敛在 `web/js/config.js` 的 `appName` 一处，提示词里的助手人格名也读它，改名只需改这一行。
